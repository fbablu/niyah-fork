## Hard guardrails (the loop must never violate these)

1. **No money-path / no security edits.** Do NOT touch `functions/`, `firestore.rules`,
   anything under auth/payments/Stripe/Plaid, `src/store/walletStore.ts`,
   `src/store/sessionStore.ts` money logic, `src/utils/payoutAlgorithm*`, KYC, or legal.
   UI / animation / components / non-money screens only. (Money path was just hardened
   across 3 adversarial `/vibe-security` rounds — see docs/STATUS.md. Don't disturb it.)
2. **Prefer ZERO-native-rebuild changes.** Only use deps already installed +
   pod-built: `react-native-reanimated`, `react-native-svg`, `react-native-gesture-handler`,
   `expo-haptics`, `expo-blur`, `expo-linear-gradient`, `@notifee/react-native`,
   `zustand`, `StyleSheet`. Anything needing a NEW native module (e.g. `expo-image-picker`,
   `lottie-react-native`) gets **built to the integration boundary + documented for Fardeen
   to `pnpm add` + rebuild** — never half-added in a way that breaks `pnpm build:local`.
3. **Gate every change on `npx tsc --noEmit`.** If a change can't stay typecheck-green in
   ≤2 fix attempts, revert it (leave the tree green). No commit = no safety net, so the
   working tree must always compile. Run the relevant Jest file (Node 20, see §Toolchain)
   when touching a tested component.
4. **Minimal & satisfying, don't overdo it.** Simple > clever. No modal stacking, no button
   fatigue, no gratuitous motion. Every animation must be fast (≤~300ms), purposeful, and
   give a small hit of dopamine — not slow the user down. Respect `prefers-reduced-motion`.
5. **No new user-facing copy that breaks the language rule** (no bet/wager/gamble/win; use
   stake/commitment/goal/complete/Earned). No VAIL/Dr. White.

## Toolchain gotchas (learned tonight)

- **pnpm 11.5.1 needs Node ≥22.13** → it crashes on Node 20 (`node:sqlite` missing). So the
  per-iteration gate uses **`npx` directly on default Node 26**: `npx tsc --noEmit`,
  `npx eslint .`, `node --import tsx --test functions/src/*.test.ts`.
- **Client Jest breaks on Node 26** → run it on **Node 20**:
  `source ~/.nvm/nvm.sh && nvm use 20 && EXPO_PUBLIC_DEMO_MODE=true npx jest <file> --no-coverage`.
- Allowed Bash: file edits, `pnpm/npx/node`, read-only git (`status/diff/log/branch/fetch/stash`).
  Denied: `git commit/push/merge`, `firebase deploy`, `rm`.

## Architecture of the loop

- **Main loop (Claude) does the implementation** — serial, typecheck-gated file edits, so
  the single un-committed working tree never gets corrupted by parallel writers.
- **Workflows do read-only fan-out** — discovery sweeps (map opportunities) + multi-lens UX
  critique panels (minimalism / native-feel / dopamine-without-overdoing) + inefficiency
  hunts. Their findings drive what the main loop builds next.
- Each iteration: pick top backlog item → implement → `tsc` gate → critique workflow →
  apply fixes → append to `progress.md` → next.

## Deferred — friends row memoization (rank 1+4) — needs a focused, reviewed pass

The documented friends list-jank fix: a single follow-toggle re-renders **all** rows because
`loadingUids` (a new object each toggle) + per-render inline-arrow handlers churn every render. The
safe parts shipped (StandingRow memo, standings skeleton, partner selector). The remaining restructure
is intricate on a 1100-line file with **no UI test coverage** + no commit rollback, so it's left for a
deliberate pass. Exact plan:

1. `React.memo` `FollowingRow` + `PartnerRow` (assign-then-memo, like Confetti/StandingRow — no reindent).
2. Give each row a `uid` prop; change its handlers to `(uid: string) => void` and bind **inside** the
   row (`onPress={() => onOpen(uid)}`) so the row's *props* stay reference-stable.
3. `useCallback` `handleUnfollow`, `handleToggleFollow`, and a new `handleOpenUser` (the `router.push`).
4. In `renderItem`, pass those stable callbacks + `uid` + `unfollowLoading={!!loadingUids[uid]}` instead
   of inline arrows. Net: a follow-toggle re-renders only the one toggled row (memo skips the rest);
   `renderItem` may still depend on `loadingUids`.
5. Verify follow / unfollow / open-profile still work on all three tabs (following/partners/standings) —
   no automated coverage, so manual device check or a new RTL test.
